我是如何將 MagicToy(SwiftData) 的剪切板性能提升了將近100倍

MagicToy 的剪切板功能支持複製文字、帶有格式的代碼或表格、網頁、圖片等。

當用戶複製了大量的圖片，或者圖片數量雖然不多，但是單個圖片的尺寸非常大，會造成剪切板非常卡頓。

MagicToy 致力於爲用戶提供好用的各種小工具，而一個卡頓的剪切板和“好用”離了十萬八千里。

趁着爲 MagicToy 添加直接粘貼到其它程序功能的機會，我準備着手修復這個問題。經過非常小的修改，MagicToy 的剪切板加載10張5K圖片的性能提升了接近100倍（從1300ms變成了從15ms），想知道我是怎麼做的嗎？請繼續往下看。

爲了更清楚地展示我是如何修復這個問題，最好向各位說明一下 MagicToy 的剪切板的界面、數據結構和業務邏輯。

MagicToy 的剪切板是什麼樣子

MagicToy 希望爲用戶提供一個簡單，但是安全的剪切板。這就是它的樣子：

如果你不喜歡它默認的樣子，你可以在十餘種精美的主題中選擇你喜歡的一個。你甚至可以自定義它的各個部分的顏色、字體、大小、邊框等等。

但是最重要的，還是它是一款安全的剪切板。通過設置剪切板項目的最長保留時間，它將幫助您減少敏感信息的暴露時間，從而保護您的密碼、賬戶、錢包祕鑰或者助記詞等等。

此外，它還支持預覽代碼、文字、圖片、備註、搜索、收藏。

而今天我們要說的，就是這個支持顯示圖片以及預覽圖片的功能。

如上所示，MagicToy 使用 SwiftData 存儲剪切板數據。SwiftData簡化了用戶使用sqlite的步驟，比CoreData更簡單（實際上我學習Swift及SwiftUI只用了半天的時間，我曾經嘗試過CoreData但根本沒有配置成功）。通過.externalStorage，我將剪切板的數據存放到了表外空間。

MagicToy存在的問題

通過觀察 Xcode 的控制檯輸出的 sql 日誌，我發現了兩個問題：

  1. 當鼠標懸浮到剪切板列表的時候，發生了sql查詢
  2. 當查詢尺寸巨大的圖片的時候，單條sql的執行時間非常慢，可能要100ms左右

所以我需要做的，就是

  1. 減少沒有必要的查詢，比如鼠標懸浮到列表上，這種場景根本無需查詢。我需要搞明白爲什麼會發生重新渲染
  2. 壓縮圖片，減少加載剪切板項目時，從數據庫讀取數據的時間

修復

減少無必要的查詢

這是最簡單的一步。

當鼠標懸浮到剪切板項目時，整個ClipboardView發生了重新渲染，而罪魁禍首就是@State修飾的hoveringItem。

通過將懸浮的邏輯從List，轉移到List中的每一個條目，該問題可以很簡單的解決掉。

優化數據結構，並利用縮略圖減少數據加載時間

只有用戶希望粘貼的時候，我們才需要提供給用戶原圖。除此以外的場景，如剪切板條目以及預覽場景，使用多個大小不一的縮略圖即可。

當程序啓動，剪切板加載數據的時候，只需要加載縮略圖，當用戶粘貼的時候，再讀取原圖，可以大大減少數據加載的時間。

基於此思路，我需要實現兩個功能：

  1. 生成縮略圖
  2. 分離縮略圖和原圖的數據到不同的表

extension NSImage {
    func resize(_ to: CGSize, isPixels: Bool = false) -> NSImage {
        
        var toSize = to
        let screenScale: CGFloat = NSScreen.main?.backingScaleFactor ?? 1.0

        if isPixels {
            
            toSize.width = to.width / screenScale
            toSize.height = to.height / screenScale
        }
    
        let toRect = NSRect(x: 0, y: 0, width: toSize.width, height: toSize.height)
        let fromRect =  NSRect(x: 0, y: 0, width: size.width, height: size.height)
        
        let newImage = NSImage(size: toRect.size)
        newImage.lockFocus()
        draw(in: toRect, from: fromRect, operation: NSCompositingOperation.copy, fraction: 1.0)
        newImage.unlockFocus()
    
        return newImage
    }
}

並且在需要使用這些數據的地方，修改爲使用縮略圖，而只有在粘貼的時候，纔去加載未壓縮的原始數據。

沒錯，SwiftData 爲你做好了這些按需加載的操作，你只需要想清楚你要什麼即可。

通過這樣的改動，MagicToy的剪切板即使沒有在內存中做任何緩存，速度也提升了將近100倍。
